# Fiscal delivery worker

A clinic can record sales, take payments and operate its cash drawers before enabling tax submission. The optional worker processes only clinics with an enabled issuer profile for its configured environment.

For a new database, the PostgreSQL bootstrap creates the limited `vetx_fiscal_worker` group. For an existing installation, a database administrator can run `psql -f infrastructure/postgres/enable-fiscal-worker.sql` in the migrated database. Give a dedicated, unprivileged login membership in that group. Store its connection URL as `FISCAL_DATABASE_URL` in the worker's environment. The worker checks that the login lacks superuser and row-security bypass privileges. The API uses its own runtime login.

Build with `pnpm exec turbo run build --filter=@vetx/worker`. Provision an issuer through `pnpm --filter @vetx/worker run provision /absolute/path/to/profile.json`. The JSON contains `organizationId`, `clinicId`, `environment` (`sandbox` or `production`), the verified `startingNumber`, an `enabled` boolean, and a `profile` object. Within the profile supply the branch (three digits), terminal (five digits), software provider ID, six-digit activity, issuer name and email, issuer identification type and number, and fiscal address with province, canton, district and details. The command preserves an existing consecutive number under repeat provisioning. A disabled profile pauses new requests and worker claims.

Mount each issuer's credentials in a read-only directory at `FISCAL_SECRETS_DIR/<environment>/<organizationId>/<clinicId>/`. Files are `issuer-number`, `username`, `password`, `certificate.pem`, `private.pem`, an optional `passphrase`, `policy-url`, `policy-sha256` (Base64) and `policy.pdf`. Supply the clinic's own API account and signing material through deployment secret management. The API and Redis never receive those credentials.

Set `FISCAL_ENVIRONMENT`, `FISCAL_REDIS_URL`, `FISCAL_POLL_SECONDS`, `FISCAL_LEASE_SECONDS`, `FISCAL_BATCH_SIZE`, and the HTTP settings in the [reception guide](../../docs/hacienda-reception.md). Provide the current environment's authentication and reception endpoints. The lease must exceed five HTTP timeouts so one delivery can authenticate, send and reconcile. Install libxml2's `xmllint`, then start the process with `pnpm --filter @vetx/worker start`.

PostgreSQL stores the issued sale snapshot, matching fiscal sequence and exact signed XML. BullMQ schedules polling and contains no invoice payloads. A recovered worker checks the original key before retransmission. An intake acknowledgement remains pending until the authority reports its decision. Accepted or rejected invoices retain their receipt, and a reported decision can be shown while its receipt is still pending. A clinic administrator can retry a blocked invoice after its configuration has been corrected. Keep official credentials and production delivery disabled in automated tests.
